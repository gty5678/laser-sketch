# 工程数据与兼容边界

## 已发布的 Android 本地数据

原有工程目录、applicationId 与旧 `project.json` 字段保持兼容。测量 SQLite 已进行兼容升级，详见 [测量仓库](measurement-repository.md)。

- 旧草稿原件仍在应用内部 `sketch-projects/<UUID>/project.json`，预览为 `preview.png`；迁移后编辑保存到统一仓库 `projects/<散列ID>.lsk`，不改写原件。
- `version` 仍为 1；`id`、`name`、`updatedAt` 保持原义。
- 墙 `start/end` 存中心线坐标，`controlLine` 为 `CENTER/INNER/OUTER`，缺省为中心线。
- 门窗仍以 `wallId` 指向宿主、`position` 存沿墙的归一化中心比例，两个门翻转字段分别保存。
- 柱仍保存原有宽、深、类型和 `rotationDegrees`。
- 照片标注旧原件继续保留原格式，新的编辑写入 `.lsk`；测量旧记录已迁入统一记录表，保留原值、字节和操作标签。

旧草图由共享迁移器读取后接入统一仓库，旧照片由共享迁移器读取后也接入统一仓库；孤立门窗在兼容转换/工程恢复时被过滤，继续遵守现有行为规范。

## 共享引擎的语义模型

`SketchDocument.formatVersion = 1` 表示当前核心模型版本，不表示旧 `project.json` 已转换为新的跨平台文件。

| 对象 | 共享模型语义 | 旧数据转换 |
| --- | --- | --- |
| Vec2 | 有限 Double、毫米 | Float 扩精度，保存旧格式时转回 Float |
| Wall | start/end 是当前定位线 | 从旧中心线按厚度及 controlLine 计算定位线 |
| Alignment.CENTER | 墙体中心位于定位线 | CENTER |
| Alignment.LEFT | 墙体位于定位线左侧（正法线） | INNER，旧定位线是中心线的负法线侧 |
| Alignment.RIGHT | 墙体位于定位线右侧（负法线） | OUTER，旧定位线是中心线的正法线侧 |
| Opening.offset | 门窗中心到宿主定位线起点的毫米距离 | position × 墙长；反向保存时 offset / 墙长 |
| Opening.flipped/hingeFlipped | 开向/铰链端独立属性 | 原字段一一对应 |
| RectColumn | 中心、宽、深、角度（度） | 原参数对应 |
| CircularColumn | 中心、直径 | 旧 width 为直径，旧 depth 无圆柱几何意义 |

模型不保存 Polygon、边线、Path、Canvas、选中状态、预览或屏幕视图。门窗随墙移动和旋转；改变墙端时保持相对固定端的毫米距离，不能按比例重新布置。

## 已实现的 `.lsk` 编解码与仓库

共享 `ProjectSerializer` 编解码四份 UTF-8 JSON；Android `AndroidProjectArchive` 将它们和照片资产组合为 ZIP。`AndroidProjectRepository` 实现统一保存、加载、列举、删除、导入和导出。这些 API 已有往返测试。首页草图/照片列表和两个编辑页面已接入应用级 ProjectServices，旧草图与照片工程均自动迁移。首页“导入项目副本 (.lsk)”通过系统文件选择器读取；草图和照片卡片的菜单可导出完整项目。

| ZIP 条目 | 内容 |
| --- | --- |
| manifest.json | LaserSketch、formatVersion=1、unit=mm、项目 ID/名称/时间、资产 ID/路径/MIME/可选像素尺寸 |
| sketch.json | 模型版本、定位线墙、毫米偏移门窗、语义柱、测量绑定 |
| measurements.json | 测量 ID、Double 毫米值、Long 时间戳、可选设备/加减/累计值、原始帧 rawHex、旧操作文案 |
| annotations.json | 按 photoAssetId 分组的有序标注；坐标为照片比例，保存文本、颜色和样式参数 |
| assets/... | Manifest 明确声明的原始资产字节 |

字段区分交换版本与 SketchDocument 版本。门窗 offset 为中心距宿主起点的毫米距离；墙 start/end 为定位线，不是旧中心线。格式不写派生多边形、屏幕状态、Undo 或 Bitmap。四份 JSON 必须齐全，未知字段、重复字段（含转义后的同名字段）、重复 ID、错误类型、无效几何/引用被拒绝；未知版本和单位有独立失败原因，目前没有隐式升级规则。

JSON 单条目最多 8 Mi 字符、嵌套最多 64 层。ZIP 默认单份元数据最多 32 MiB、单份资产最多 128 MiB、总解压大小最多 256 MiB、条目最多 4096；按实际读取字节检查，不能只相信 ZIP 头。拒绝重复条目、路径穿越、目录、未知/缺失资产和无效 UTF-8。读取在内存中完成，不把 ZIP 路径直接解压到文件系统。流由调用方关闭。

仓库只操作宿主指定的独立内部目录，逻辑项目 ID 经 SHA-256 映射为文件名。保存先写同目录临时文件、同步，再原子替换；校验或写入失败保留上次工程，清理临时文件。仅修改项目元数据时按资产 ID 保留原照片；新增资产须通过带字节的保存或导入 API 提供，不能生成空占位照片。

导入始终生成新的项目 UUID 和导入时间，名称、几何、照片字节、标注、项目内测量与绑定保持不变；同一文件多次导入得到独立副本，不覆盖本机工程。底层保留原 ID 的导入 API 也拒绝覆盖已存在项目。资产、实体与测量 ID 属于项目内部引用，无需因项目 UUID 改变而重写。无效容器在写入前拒绝，不向目录流发布半个项目。

导出包含项目的全部分区与资产，即使从照片卡片发起也保留草图和测量。系统文件选择器授予的 URI 由应用级 IO 队列立即使用，平台负责打开和关闭流；队列只持有应用 Context，页面销毁不取消已接受的工作。导出选择器尚未返回时的项目 ID 存入 Activity 状态，重建后可继续。取消选择不会读写文件；无需增加存储权限。迁移成功和写入确认前不得删除原始数据。

## 已建立的统一项目模型

`Project` 组合 Manifest、语义 SketchDocument、MeasurementRecord、按照片资产分组的 AnnotationDocument、资产元数据及 MeasurementBinding。模型只描述数据与逻辑引用，不携带 Bitmap 或派生轮廓。

Manifest 固定当前交换格式版本 1、`LaserSketch` 和 `mm`；项目模型会拒绝未知版本/单位，编解码器在创建模型前拒绝不支持的版本，后续迁移须显式处理。资产使用 `assets/` 内的相对路径，拒绝绝对路径、空路径段、`.` / `..`、反斜杠、冒号和 NUL；ID 与地图键、路径唯一性必须一致。每份照片标注文档引用自身的图片资产。测量 ID 不能重复，Binding 必须引用已存在的测量及正确类型的草图目标。

`ProjectRepository` 的共享接口、共享 JSON 编解码器及 Android ZIP/原子文件仓库已实现。`ProjectMigration` 与 Android 原文件复制适配器已实现，草图和照片页面均已接入统一仓库，不再通过旧 Store 保存。原文件路径保持兼容。

## 旧 Android 工程迁移

`ProjectMigration` 为纯共享转换器：接受旧 version=1 JSON（缺省版本按旧版 1），保留 Double 坐标、Long 时间戳、实体 ID、标签和样式；未知版本、错误类型、重复 ID、零长度墙或越界洞口拒绝整个目标。缺省墙/柱/门窗参数保持旧 Store 语义；缺失实体 ID 使用类型与数组索引生成确定性 ID。旧 INNER/OUTER 的中心线按半墙厚平移到定位线，门窗 position × 宿主墙长成为 offset。

照片尺寸/文字/角度/面积按原分组顺序生成稳定 ID，照片坐标不换算成毫米。遵守原恢复行为，孤立门窗和少于三点的未完成面积会过滤，并以 MigrationNotice 返回，调用界面须显式处理这些提示。其余无效状态不能偷偷丢弃。

`AndroidLegacyProjectMigration` 扫描旧草图与照片目录，将逻辑 ID 分别映射为 `sketch-<旧ID>` 和 `annotation-<旧ID>`，避免两个目录碰巧有相同 UUID 时互相覆盖。检查文件元数据 ID 与目录 ID 一致，限定固定子文件与读取大小，严格解码 UTF-8；照片原始字节复制进 `.lsk`。迁移逐工程提交，单个损坏工程返回失败原因，其他工程继续。迁移成功后仓库在同目录写入按逻辑 ID 散列命名的 `.migrated` 记录，工程删除后仍保留该记录，避免保留的旧文件被再次导入。已有目标工程先校验后补上记录；已有记录的工程跳过。仓库 `saveIfAbsent` 在同一实例锁内再次检查工程和记录，不能覆盖之后的编辑。源 JSON、照片和预览全部保留；应用容器初始化、首页刷新和旧工程 ID 打开时自动迁移草图与照片，迁移后没有双写。

验证覆盖三个定位线、门窗毫米偏移、圆柱直径、四种照片标注、样式和确定性 ID、版本/无效输入、两类同 ID 工程、重复执行、损坏工程隔离，以及 Android 实际 JPEG 原字节保留和文件原子替换。测量 SQLite 的兼容升级独立处理，见 [测量仓库](measurement-repository.md)。

## 共享项目服务与保存边界

`ProjectService` 在同一应用实例内串行处理创建、加载、改名、删除及分区保存，并通过 StateFlow 发布不含图片字节的项目目录。Sketch 保存只替换草图，Annotation 保存只替换指定照片文档；两者同时提交时会重新读取最后确认的工程，保留其他分区、资产、测量与名称。删除草图实体时移除已经没有有效目标的测量 Binding，不删除测量历史。没有实际变化时不写文件或更新时间，写入失败不发布新目录状态。

Android `ProjectServices` 持有一个应用级服务及串行 IO 请求队列。首页草图和照片列表观察目录流，新建/改名/删除使用同一队列；SketchActivity 异步打开，加载成功前禁止画布编辑。保存直接提交共享编辑器的已确认 Double 文档，PNG 预览写入独立缓存；临时拖动文档不能进入持久化。页面停止先取消拖动再提交，页面销毁只取消 UI 等待，应用队列仍完成保存。后台失败保留待展示状态，回到首页后提示；迁移失败/过滤提示也保留到界面确认。AnnotationActivity 同样使用该容器，暂停时取消拖动、保存当前资产文档；打开和读取用生命周期协程替代原裸线程，取消时回收尚未交给 View 的 Bitmap。

新选取/拍摄的照片在 AndroidPhotoCodec 中读取、按原行为限制长边采样、JPEG 编码后作为资产保存；打开时显示仓库中的像素，图片字节不进入共享文档。选择另一张照片创建独立工程，避免显示新图片却继续引用旧原图。创建前预留项目 ID 并保存在实例状态中，重复提交同一 ID 返回已保存工程，不能覆盖其照片和已确认标注。一个工程的多个照片文档分别使用资产 ID，首页可选择照片；保存一个照片文档保留其他分区。

## 墙面尺寸的兼容扩展

`sketch.json` 增加可选 `dimensions` 数组；没有标注时不写该字段，旧工程读取为无标注。每项包含 `id`、`first`、`second`、`position`，`position` 为毫米世界坐标的尺寸线定位点。尺寸值由当前参考线几何派生，不保存文字值或锁定约束。两端分别使用以下互斥结构：

- 墙：`{wallId, side}`，`side` 为相对墙 start→end 的 `LEFT`、`RIGHT` 物理侧、`CENTER` 实体中心线，或 `START`、`END` 两端横跨墙厚的短边；短边端点由对应端的左右物理边确定，随墙方向、厚度及定位线设置重算。旧左右墙面结构和含义不变，已有工程无需迁移；新增短边沿用可选尺寸数组中的引用结构。
- 门窗：`{openingId, side}`，`side` 为 `START`、`END` 洞口边框或沿墙的 `LEFT`、`RIGHT` 边框，与门扇翻转无关。
- 柱：`{columnId, line}`，`line` 为 `LEFT`、`RIGHT`、`TOP`、`BOTTOM`、`CENTER_X`、`CENTER_Y`；矩形柱使用随旋转的局部坐标，圆柱使用世界水平/垂直轴与四向切线。

重复 ID、悬空对象引用、混用多个对象键和无效坐标拒绝导入。同一对象引用仅允许同一 `wallId` 的 `START` 与 `END` 配对，表示几何墙长；顺序保留，尺寸驱动时 `first` 为固定端、`second` 为移动端。其他同对象组合拒绝导入。允许不同对象的 ID 字符串相同，引用类型区分所属集合。非平行引用保留为失效标注，不伪造数值。

版本 1 的既有字段含义和旧工程原件保持不变。此为新读取器对版本 1 的可选字段扩展；旧版读取器严格拒绝未知字段，因此含标注的新工程不能交给旧版编辑，避免标注被静默丢失。新版本仍可打开没有该字段的既有工程。

## 独立格式回归证据

除完整项目编码/解码往返外，共享测试包含独立手写的非空 JSON 工程：LEFT 墙的 start/end 直接作为定位线，厚度 200 mm 后中心线位于其正法线侧 100 mm；门窗 offset=1800 mm、width=900 mm 被验证为实际毫米，而不是旧归一化比例。样本同时覆盖矩形柱/圆柱、Double 测量、超过 JavaScript 安全整数的 Long 时间戳、原始字节和 ID 属性绑定。该测试通过不代表桌面宿主或 Android 系统文件选择器已完成实机验收。

# LaserSketch KMP 跨平台与轻量几何引擎改造方案

## 1. 改造目标

LaserSketch 移动端定位为：

**Android / iOS 现场空间测量、轻量草图和照片记录工具。**

移动端不发展为完整 CAD，也不承担复杂 BIM/CAD 几何处理。

移动端负责：

- Bosch 激光测距设备连接
- 测量数据采集
- 快速绘制墙体
- 门、窗、柱等基础建筑元素
- 简单移动、旋转、修改尺寸
- 基础 Snap
- 简单连接 / Trim / Extend
- 照片尺寸标注
- 项目管理
- 项目数据上传或导出

桌面端负责：

- 重型几何引擎
- 完整墙体拓扑
- 高级 Trim / Extend / Offset
- Constraint Solver
- 房间与空间识别
- DXF / IFC / BIM
- 大型项目
- 高精度 CAD 编辑

因此整个产品采用：

```text
             LaserSketch Document Format
                        │
           ┌────────────┴────────────┐
           │                         │
     LaserSketch Mobile          Desktop App
       Android / iOS               C++ Engine
           │                         │
     Light Sketch Engine        Heavy CAD Engine
           │                         │
     Kotlin Multiplatform       独立桌面实现
```

核心原则：

> 手机与桌面统一数据模型，不强制统一几何引擎实现。

# 4. 轻量几何引擎的边界

Geometry Lite 不做完整 CAD Kernel。

它只解决移动端真正需要的问题。

## 4.1 基础数学类型

禁止 Geometry Core 使用 Android / Compose 类型。

不要：

```kotlin
Offset
PointF
Path
RectF
Canvas
```

统一定义自己的类型：

```kotlin
data class Vec2(
    val x: Double,
    val y: Double
)

data class Segment2(
    val start: Vec2,
    val end: Vec2
)

data class Line2(
    val origin: Vec2,
    val direction: Vec2
)

data class Rect2(
    val min: Vec2,
    val max: Vec2
)
```

单位统一：

```text
Document / Engine:

毫米 mm
Double
```

屏幕坐标才使用 px。

因此：

```text
Geometry World
mm

      ↓ Viewport

Screen
px
```

Geometry 只解决数学问题。

例如：

```kotlin
object Geometry {

        point: Vec2,
        segment: Segment2
    ): Vec2

    fun segmentIntersection(
        a: Segment2,
        b: Segment2
    ): Vec2?

    fun lineIntersection(
        a: Line2,
        b: Line2
    ): Vec2?

    fun offset(
        segment: Segment2,
        distance: Double
    ): Segment2

    fun distanceToSegment(
        point: Vec2,
```

Geometry：

```text

不知道 UI
不知道 Canvas
不知道 Selection
不知道 Undo
```

必须尽量保持纯函数。

# 11. Topology 只做轻量实现

手机端不建立复杂 CAD 拓扑。

只维护：

```text

```

例如：

```kotlin
enum class WallEndpoint {
    START,
    END
}

data class WallEndpointRef(
    val wallId: String,
    val endpoint: WallEndpoint
)

data class WallJunction(
    val id: String,
    val position: Vec2,
    val endpoints: Set<WallEndpointRef>

```

Topology 第一阶段只需要支持：

```text

Endpoint merge
```

明确区分：

```text
Geometry Intersection
≠
Topology Connection
```

两堵墙数学上相交，不代表用户希望建立连接。

# 13. Undo / Redo

当前 snapshot undo 后续改成 Command Stack：

```kotlin

        ArrayDeque<SketchCommand>()

        ArrayDeque<SketchCommand>()

    fun redo()
}
```

# 28. 手机与桌面不共享最终几何

```json
  "start": [0.0, 0.0],
  "end": [4200.0, 0.0],
  "thickness": 200.0,
  "alignment": "CENTER"

```

而不是：

```json

  "polygon": [...]
```

桌面打开后：

```text

       ↓
Desktop Heavy Engine
       ↓
Precise Wall Geometry
       ↓
Topology
Room
BIM
```

这样桌面引擎可以不断升级，而不会影响手机。

# 43. 最重要的架构规则

整个改造过程中坚持六条：

**第一：Engine 不依赖 Android。**

```text
不能出现：
android.*
```

**第二：Engine 不依赖 Compose。**

```text
不能用：
Offset
Path
Canvas
```

**第三：Document 保存语义，不保存绘制缓存。**

保存：

```text
Wall(start, end, thickness)
```

不保存：

```text
wall polygon
```

**第四：永久修改必须通过 Command。**

```text
UI → Command → Document
```

**第五：手机与桌面共享 Document Spec，而不是共享整个 Engine。**

**第六：移动端复杂度达到 CAD Kernel 级别时，停止继续扩展，交给桌面端。**
